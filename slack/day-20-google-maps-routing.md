# System Design Daily

## Day 20/40: 길찾기는 세계 전체가 아닌 필요한 그래프만 읽는다

### 오늘의 질문

- 서울에서 부산까지 길을 찾을 때 모든 골목길을 같은 정밀도로 메모리에 올려야 할까요?

### WHY: 전 세계 도로 그래프는 한 번에 탐색하기엔 너무 크다

길찾기는 교차로를 노드, 도로를 간선으로 표현한 그래프 문제입니다. Dijkstra나 A*를 사용할 수 있지만 세계 전체 도로를 한 그래프로 읽으면 메모리와 탐색 시간이 너무 큽니다. 장거리 경로에서 출발지 골목은 자세히 봐야 하지만 고속도로 구간은 같은 수준의 세부 정보가 필요하지 않습니다.

도로 그래프를 지역별 Routing Tile로 나누고, 거리 수준에 맞는 계층을 사용하면 필요한 그래프만 불러올 수 있습니다.

### WHAT: 계층형 Routing Tile과 서비스 분리

Routing Tile은 지역 도로 그래프와 이웃 타일 연결 정보를 담습니다. 가까운 구간은 상세 타일을, 먼 구간은 주요 도로만 남긴 상위 타일을 사용합니다. 원시 도로 데이터는 오프라인 파이프라인에서 정규화하고 타일로 변환해 객체 저장소에 저장합니다.

Navigation Service는 여러 역할을 조합합니다.

- Geocoding Service가 출발지와 목적지를 좌표로 바꿉니다.
- Route Planner가 후보 경로를 만듭니다.
- Shortest Path Service가 Routing Tile에서 A* 변형을 실행합니다.
- ETA Service가 현재 교통과 과거 패턴으로 시간을 예측합니다.
- Ranker가 통행료 회피, 이동 수단 같은 조건으로 후보를 정렬합니다.

### HOW: 경로와 ETA를 분리해 계산한다

최단 거리와 최단 시간은 다릅니다. 도로 길이는 비교적 안정적이지만 속도는 시간대, 사고, 공사에 따라 바뀝니다. 기본 그래프에서 후보 경로를 구한 뒤 ETA Service가 실시간 교통 가중치를 적용합니다.

```text
origin, destination
  -> geocoding
  -> 관련 routing tile 선택
  -> 후보 경로 탐색
  -> 교통 기반 ETA 계산
  -> 사용자 조건으로 ranking
  -> polyline, 안내, ETA 반환
```

경로가 절대 최적일 필요보다 제한 시간 안에 정확하고 합리적인 답을 주는 것이 중요할 수 있습니다. 탐색 상한을 두고 좋은 후보를 먼저 반환한 뒤, 필요하면 대안을 추가합니다.

### 실시간 교통과 재탐색

위치 업데이트 스트림에서 도로 구간별 속도를 추정하고 사고 이벤트를 만듭니다. 현재 길 안내 중인 사용자가 어떤 Routing Tile을 지나갈지 역인덱스를 두면 사고가 난 타일의 사용자만 골라 재탐색할 수 있습니다.

모든 사용자의 세부 타일 전체를 저장하면 데이터가 커집니다. 출발지 상세 타일과 상위 계층 타일을 함께 기록해 사고 타일이 경로 범위에 포함되는지 빠르게 좁힐 수 있습니다. 영향을 받을 가능성이 있는 사용자에게만 새 ETA나 대체 경로를 계산합니다.

WebSocket은 서버가 재경로 정보를 밀어주고 클라이언트가 위치를 보내는 양방향 흐름에 맞습니다. 연결이 끊기면 클라이언트는 마지막 경로를 계속 사용하고, 재연결 후 현재 위치에서 경로를 다시 요청해야 합니다.

### 실패 모드와 안전성

교통 데이터가 늦었다고 잘못된 길 안내를 내면 안 됩니다. ETA 정확도와 경로 유효성을 분리합니다. 실시간 교통이 없으면 도로 폐쇄 같은 안전 제약은 최신 확정 데이터로 막고, ETA는 과거 평균으로 낮춰 계산합니다.

Routing Tile 버전이 섞이면 연결 도로가 맞지 않을 수 있습니다. 한 요청은 같은 그래프 버전을 사용해야 합니다. 새 타일 세트를 불변 경로에 배포하고 manifest를 전환합니다.

### 함정 체크

- 전 세계 도로를 한 그래프로 읽으면 메모리와 탐색 시간이 감당되지 않습니다.
- 최단 거리만 최적화하면 교통 체증과 사용자 조건을 반영하지 못합니다.
- 사고가 날 때 모든 운전자의 경로를 다시 계산하면 재탐색 폭주가 생깁니다.
- 서로 다른 버전의 Routing Tile을 한 탐색에서 섞으면 경계 연결이 깨질 수 있습니다.

### 오늘의 한 문장

> 대규모 길찾기는 전 세계 그래프를 푸는 문제가 아니라 필요한 해상도의 타일만 이어 붙이고 변한 구간만 다시 계산하는 문제입니다.

### 30초 확인 문제

사고 이벤트 하나가 들어올 때 길 안내 중인 모든 사용자의 경로를 다시 계산하고 있습니다. 무엇을 추가해야 할까요?

### 정답과 해설

Routing Tile에서 현재 경로를 지나는 사용자로 이어지는 역인덱스를 둡니다. 사고 타일과 겹치는 사용자만 후보로 고른 뒤 새 ETA와 대체 경로를 계산합니다. 계층형 타일 범위를 저장하면 장거리 경로도 적은 키로 영향 여부를 좁힐 수 있습니다.
