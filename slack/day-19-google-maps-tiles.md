# System Design Daily

## Day 19/40: 지도는 거대한 한 장이 아니라 타일 묶음이다

### 오늘의 질문

- 세계 지도 전체가 수십 PB라면 휴대폰은 현재 화면을 어떻게 즉시 그릴까요?

### WHY: 사용자는 세계 전체가 아니라 화면 한 조각만 본다

지도 데이터를 한 장의 이미지로 만들면 확대할수록 해상도가 부족하고, 작은 이동에도 거대한 파일을 다시 받아야 합니다. 사용자는 특정 위치와 줌 레벨의 작은 영역만 봅니다. 따라서 지도를 여러 크기의 타일로 미리 나누고 필요한 조각만 전송해야 합니다.

Web Mercator 같은 투영법으로 구면의 좌표를 평면에 옮기고, 각 줌 레벨을 격자로 분할합니다. 낮은 줌에서는 한 타일이 넓은 지역을 담고, 줌이 한 단계 높아질 때 타일 수는 네 배가 됩니다.

### WHAT: 정적 타일과 위치 검색

Raster Tile은 서버가 미리 그린 이미지입니다. 클라이언트 구현이 단순하지만 스타일마다 별도 이미지를 만들고 전송량이 큽니다. Vector Tile은 도로, 경계, 라벨을 경로와 속성으로 전송하고 클라이언트가 그립니다. 대역폭과 스타일 변경에는 유리하지만 기기 렌더링 비용이 늘어납니다.

타일은 객체 저장소에 두고 CDN으로 제공합니다.

```text
/z/{zoom}/x/{tile_x}/y/{tile_y}.pbf
```

같은 타일을 많은 사용자가 반복해서 보므로 CDN 적중률이 높습니다. API Server가 매 요청마다 지도를 동적으로 그리면 CPU 부하가 커지고 캐시 키도 복잡해집니다.

### HOW: 화면 이동을 타일 요청으로 바꾼다

클라이언트는 현재 중심 좌표, 화면 크기, 줌 레벨에서 필요한 타일 좌표를 계산합니다. 화면 가장자리 바깥의 타일을 조금 미리 받아두면 이동할 때 빈 화면이 줄어듭니다. 너무 멀리 prefetch하면 모바일 데이터와 배터리를 낭비하므로 이동 방향과 속도를 반영합니다.

타일 URL 계산 로직을 클라이언트에 넣으면 API 호출을 줄일 수 있습니다. 대신 타일 체계를 바꾸기 어렵습니다. 서버가 타일 URL 목록을 반환하면 버전 전환은 쉽지만 요청이 하나 늘어납니다. 장기 호환성이 중요하면 URL에 타일 스키마 버전을 명시합니다.

주소 검색은 타일 조회와 다릅니다. Geocoding Service가 주소를 위도와 경도로 바꾸고, reverse geocoding은 좌표를 장소로 바꿉니다. 장소 인덱스는 읽기가 많고 갱신이 적으므로 캐시를 앞에 둘 수 있습니다. 지도 렌더링 데이터와 장소 검색 데이터를 한 저장소에 억지로 합치지 않습니다.

### 위치 업데이트의 역할

클라이언트 위치는 일정 간격으로 배치 전송할 수 있습니다. 쓰기 부하가 크므로 위치 이력은 Cassandra 같은 write-heavy 저장소에 두고, Kafka로 교통 분석과 지도 개선 파이프라인에 전달합니다. 지도 타일 요청과 위치 이력 쓰기 경로를 분리해야 한쪽의 폭주가 화면 렌더링을 막지 않습니다.

### 실패 모드와 운영

타일을 갱신할 때 같은 URL의 내용을 즉시 덮어쓰면 CDN마다 다른 버전을 제공할 수 있습니다. 불변 버전 URL을 만들고 manifest가 새 버전을 가리키게 합니다. CDN 장애나 캐시 미스 폭주에 대비해 origin 보호와 요청 병합이 필요합니다.

클라이언트 캐시에는 디스크 상한과 만료 정책을 둡니다. 오래된 타일이 잘못된 도로를 보여줄 수 있으므로 지도 데이터의 중요도에 따라 TTL을 다르게 설정합니다.

### 함정 체크

- 타일을 요청마다 동적으로 렌더링하면 CPU 비용과 응답 변동이 커집니다.
- 줌 레벨을 무시하고 같은 이미지를 확대하면 정보 밀도와 라벨 품질이 무너집니다.
- 타일 좌표 계산을 클라이언트에 고정하면서 버전 필드를 빼면 체계를 바꾸기 어렵습니다.
- 위치 수집 파이프라인 장애가 지도 타일 제공까지 전파되면 안 됩니다.

### 오늘의 한 문장

> 지도 렌더링은 거대한 지도를 보내는 일이 아니라 화면과 줌에 맞는 불변 타일을 빠르게 조합하는 일입니다.

### 30초 확인 문제

도로 데이터 갱신 뒤 어떤 사용자는 새 타일을 보고 다른 사용자는 오래된 타일을 봅니다. 같은 URL을 덮어쓴 것이 원인입니다. 어떻게 배포해야 할까요?

### 정답과 해설

새 버전 경로에 타일을 모두 생성하고 검증한 뒤 manifest나 API가 새 버전 URL을 가리키게 합니다. URL이 불변이면 CDN과 클라이언트 캐시가 서로 다른 내용을 같은 키로 보관하지 않습니다. 이전 버전은 안전한 유예 기간 동안 남겨 진행 중인 세션을 보호합니다.
