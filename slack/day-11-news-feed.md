# System Design Daily

## Day 11/40: 뉴스 피드는 누구에게 언제 펼칠 것인가

### 오늘의 질문

- 팔로워 20명인 사용자의 글과 팔로워 2천만 명인 사용자의 글을 같은 방식으로 배포해도 될까요?

### WHY: 피드의 병목은 조회보다 배포에서 생긴다

뉴스 피드는 여러 작성자의 게시물을 한 화면에 모읍니다. 단순하게 생각하면 사용자가 앱을 열 때 친구 목록을 읽고, 각 친구의 최신 글을 모아 정렬하면 됩니다. 하지만 친구가 5천 명이고 사용자가 동시에 몰리면 조회 한 번이 수천 개 읽기로 번집니다.

반대로 글을 쓸 때 친구들의 피드에 게시물 ID를 미리 넣으면 조회는 빨라집니다. 대신 팔로워가 많은 작성자 한 명이 글을 올릴 때 수백만 건의 쓰기가 터집니다. 핵심은 읽기와 쓰기 중 한쪽 비용을 없애는 것이 아니라, 사용자 특성에 따라 비용을 옮기는 것입니다.

### WHAT: 쓰기 시점과 읽기 시점의 팬아웃

**Fanout on write**는 게시물을 작성할 때 수신자의 피드 캐시에 게시물 ID를 밀어 넣습니다.

- 장점: 피드 조회가 빠르고 응답 시간이 예측 가능합니다.
- 단점: 비활성 사용자에게도 쓰기가 발생하고, 유명 계정의 글이 쓰기 폭풍을 만듭니다.

**Fanout on read**는 사용자가 피드를 열 때 팔로우한 작성자의 글을 가져와 합칩니다.

- 장점: 실제로 읽는 사용자에게만 비용을 씁니다.
- 단점: 팔로우 수가 많을수록 조회 지연과 저장소 부하가 커집니다.

실무에서는 둘을 섞습니다. 보통 사용자는 쓰기 시점에 팬아웃하고, 팔로워가 많은 계정은 읽기 시점에 합칩니다. 피드를 열 때는 미리 만든 피드와 유명 계정의 최신 글을 병합한 뒤 시간순이나 랭킹 점수로 정렬합니다.

### HOW: 게시물 본문 대신 ID를 배포한다

```text
게시물 작성
  -> Post Service가 본문 저장
  -> Fanout Service가 친구 목록과 공개 범위 확인
  -> Queue에 <receiver_id, post_id> 적재
  -> Worker가 receiver의 feed cache 갱신
```

피드 캐시에는 전체 게시물 객체가 아니라 `(post_id, author_id)` 같은 작은 참조를 저장합니다. 사용자가 피드를 요청하면 News Feed Service가 ID 목록을 읽고, Content Cache에서 본문을 묶어서 가져옵니다. 소셜 그래프, 좋아요 수, 작성자 정보도 별도 캐시로 분리하면 한 종류의 데이터가 갱신될 때 피드 전체를 다시 쓰지 않아도 됩니다.

큐는 순간 트래픽을 흡수하지만 지연을 숨기기도 합니다. 큐 적체 시간, 팬아웃 처리량, 피드 캐시 쓰기 실패율을 함께 봐야 합니다. 재시도는 같은 게시물을 중복 삽입할 수 있으므로 `(receiver_id, post_id)`를 멱등 키로 사용합니다.

### 실무 예와 트레이드오프

뮤트, 차단, 공개 범위는 팬아웃 전에 적용해야 합니다. 필터를 나중에 적용하면 노출하면 안 되는 게시물 ID가 수신자 캐시에 남습니다. 권한 변경이 잦다면 조회 시점에 한 번 더 검증해 방어합니다.

최근 게시물만 캐시에 두는 것도 중요합니다. 대부분의 사용자는 첫 몇 페이지를 봅니다. 무제한 타임라인을 메모리에 보관하면 비활성 사용자의 캐시가 비용을 잡아먹습니다. 오래된 페이지는 저장소에서 읽도록 계층을 나눕니다.

### 함정 체크

- 유명 계정까지 모두 쓰기 팬아웃하면 한 게시물이 수백만 건의 캐시 쓰기를 만듭니다.
- 게시물 본문을 각 피드에 복사하면 수정, 삭제, 권한 변경이 어려워집니다.
- 큐를 넣었다고 신뢰성이 생기지는 않습니다. 중복 처리와 실패한 작업의 재처리가 필요합니다.
- 시간순 정렬만 가정한 캐시 구조는 랭킹 피드로 바뀔 때 큰 제약이 됩니다.

### 오늘의 한 문장

> 뉴스 피드는 게시물을 저장하는 시스템이 아니라, 읽기와 쓰기 사이에서 팬아웃 비용을 배치하는 시스템입니다.

### 30초 확인 문제

팔로워가 1천만 명인 계정이 글을 올렸습니다. 쓰기 팬아웃 큐가 20분 밀렸지만 일반 사용자의 피드는 정상입니다. 어떤 설계 변경을 먼저 검토해야 할까요?

### 정답과 해설

해당 계정을 읽기 팬아웃 대상으로 분류합니다. 일반 계정의 게시물은 기존처럼 수신자 피드에 미리 넣고, 유명 계정의 게시물은 사용자가 피드를 읽을 때 합칩니다. 이 방식은 유명 계정 하나가 만드는 쓰기 폭발을 줄입니다. 다만 조회 시 병합 비용이 추가되므로 유명 계정 게시물 캐시와 병렬 조회가 필요합니다.
