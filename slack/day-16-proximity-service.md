# System Design Daily

## Day 16/40: 주변 검색은 좌표를 셀로 바꾸는 문제다

### 오늘의 질문

- 위도와 경도에 각각 인덱스를 걸면 반경 500m 안의 매장을 빠르게 찾을 수 있을까요?

### WHY: 2차원 거리는 1차원 인덱스와 맞지 않는다

주변 검색은 사용자의 좌표와 반경을 받아 가까운 매장을 반환합니다. 위도 범위와 경도 범위를 SQL 조건으로 걸 수 있지만, 두 개의 독립 인덱스는 원형 거리 검색을 효율적으로 해결하지 못합니다. 후보가 많은 도심에서는 넓은 범위를 읽고 애플리케이션에서 거리를 다시 계산하게 됩니다.

해법은 2차원 공간을 검색하기 쉬운 1차원 키나 계층 구조로 바꾸는 것입니다. Geohash, Quadtree, S2 같은 공간 인덱스가 이 역할을 합니다.

### WHAT: Geohash와 Quadtree의 선택

**Geohash**는 지구를 격자로 계속 나누고 셀을 문자열로 표현합니다. 접두사가 길수록 셀이 작아집니다. 반경에 맞는 정밀도를 고른 뒤 현재 셀과 이웃 셀의 매장 ID를 읽습니다.

```text
search(lat, lng, radius=500m)
  -> precision = 6
  -> cells = current geohash + 8 neighbors
  -> business IDs 조회
  -> 실제 거리 계산
  -> radius 안의 결과 정렬
```

Geohash는 구현과 갱신이 단순하지만 셀 경계 문제가 있습니다. 아주 가까운 두 지점이 다른 접두사를 가질 수 있으므로 현재 셀만 조회하면 안 됩니다.

**Quadtree**는 한 영역의 매장이 기준 수를 넘으면 네 구역으로 재귀 분할합니다. 도심은 촘촘하게, 교외는 넓게 나뉩니다. 최근접 K개를 찾는 데 유리하지만 트리 생성과 갱신이 복잡합니다.

### HOW: 검색 경로를 ID 조회와 상세 조회로 나눈다

Location-Based Service는 무상태 읽기 서비스로 둡니다. 먼저 공간 인덱스에서 후보 `business_id`를 가져오고, Business Info Cache에서 상세 정보를 묶어서 읽습니다. 마지막으로 정확한 구면 거리를 계산해 반경 밖 후보를 제거하고 정렬합니다.

캐시 키로 GPS 좌표를 그대로 쓰면 적중률이 낮습니다. 사용자가 조금만 움직여도 키가 달라지고 GPS 오차도 있습니다. Geohash 셀을 키로 사용하면 같은 지역 요청이 캐시를 공유합니다.

```text
geohash -> [business_id...]
business_id -> name, address, category, rating
```

매장 정보는 위치 검색보다 훨씬 적게 바뀝니다. Primary DB에 쓴 뒤 Replica와 공간 인덱스에 비동기로 반영해도 몇 분의 지연을 허용할 수 있습니다. 새 매장이 즉시 검색돼야 하는 요구가 있다면 이 가정부터 바뀝니다.

### 운영과 실패 모드

Quadtree를 서버 시작 때 메모리에 만들면 몇 분 동안 트래픽을 받을 수 없습니다. 새 인스턴스를 일부만 올려 준비 상태를 확인한 뒤 점진적으로 교체합니다. 실시간 갱신은 잠금과 캐시 무효화를 복잡하게 만들므로, 변경 빈도가 낮다면 주기적 스냅샷 교체가 낫습니다.

Geohash 정밀도가 너무 낮으면 후보가 많아지고, 너무 높으면 조회할 이웃 셀이 많아집니다. 반경별 후보 수, Redis 호출 수, 거리 필터 탈락률을 측정해 정밀도를 조정합니다.

### 함정 체크

- 위도와 경도 범위만으로는 원 밖의 후보가 많이 섞입니다.
- 현재 Geohash 셀만 읽으면 경계 바로 건너편 매장을 놓칩니다.
- GPS 원본 좌표를 캐시 키로 쓰면 같은 장소의 요청도 서로 다른 키가 됩니다.
- 매장 갱신 빈도가 낮은데 실시간 트리 수정을 먼저 만들면 운영 복잡도만 커집니다.

### 오늘의 한 문장

> 주변 검색의 핵심은 거리를 매번 계산하는 것이 아니라 가까운 후보만 남도록 공간을 먼저 나누는 것입니다.

### 30초 확인 문제

사용자가 셀 경계에서 20m 떨어진 카페를 검색했지만 결과에 나오지 않았습니다. Geohash 계산은 정상입니다. 무엇을 확인해야 할까요?

### 정답과 해설

현재 셀뿐 아니라 인접 셀도 조회했는지 확인합니다. Geohash 접두사는 가까운 두 지점이 같은 셀에 속한다는 보장을 하지 않습니다. 현재 셀과 이웃 셀에서 후보를 모은 뒤 실제 거리를 계산해 반경 안의 매장만 반환해야 합니다.
