# System Design Daily

## Day 15/40: 파일 동기화는 바이트보다 버전을 맞춘다

### 오늘의 질문

- 10GB 파일에서 4KB만 바뀌었을 때 모든 기기가 10GB를 다시 받아야 할까요?

### WHY: 파일 저장과 동기화는 다른 문제다

클라우드 드라이브는 파일을 잃지 않고 보관해야 합니다. 동시에 여러 기기에서 같은 파일을 수정하고, 네트워크가 끊겼다가 돌아와도 변경분을 맞춰야 합니다. 파일 하나를 통째로 객체 저장소에 넣는 것만으로는 대역폭, 재개, 충돌, 버전 복구를 해결할 수 없습니다.

핵심은 파일을 고정 크기 블록으로 나누고, 파일 메타데이터가 어떤 블록을 어떤 순서로 조립하는지 기록하는 것입니다. 작은 수정은 바뀐 블록만 전송합니다.

### WHAT: 블록 저장소와 메타데이터 저장소

블록 서버는 파일을 예를 들어 최대 4MB 블록으로 나눕니다. 각 블록에 해시를 부여하고 압축과 암호화를 거쳐 객체 저장소에 올립니다. Metadata DB는 파일 이름, 소유자, 버전, 상태, 블록 순서를 관리합니다.

```text
file_version 42
  block 0 -> hash_a
  block 1 -> hash_b
  block 2 -> hash_c
```

다음 버전에서 두 번째 블록만 바뀌면 `hash_a`와 `hash_c`는 그대로 참조하고 새 `hash_d`만 업로드합니다. 이 delta sync는 업로드 시간과 대역폭을 줄입니다. 같은 계정 안에서 동일 해시 블록을 재사용하면 중복 제거도 가능합니다.

### HOW: 데이터 업로드와 메타데이터 커밋을 분리한다

1. 클라이언트가 업로드 세션을 만들고 대상 파일 버전을 선언합니다.
2. 변경된 블록만 Block Server를 거쳐 객체 저장소에 올립니다.
3. 블록 체크섬과 저장 완료를 확인합니다.
4. Metadata DB에 새 버전을 `pending`으로 기록합니다.
5. 필요한 블록이 모두 존재하면 상태를 `uploaded`로 원자적으로 바꿉니다.
6. Notification Service가 다른 기기에 변경 이벤트를 보냅니다.

메타데이터를 먼저 확정하면 일부 블록이 없는 버전이 보일 수 있습니다. 반대로 블록 업로드 후 메타데이터 커밋이 실패하면 고아 블록이 남습니다. 고아 블록은 즉시 지우지 말고 유예 기간 뒤 참조 수를 확인해 정리합니다.

### 충돌은 숨기지 않는다

두 기기가 같은 기준 버전에서 파일을 수정할 수 있습니다. 먼저 도착한 변경만 남기고 나머지를 덮어쓰면 데이터가 사라집니다. 서버는 새 버전 요청의 `base_version`을 현재 버전과 비교합니다.

현재 버전과 다르면 충돌 사본을 보존하고 사용자나 애플리케이션이 병합하게 합니다. 텍스트처럼 자동 병합 가능한 형식과 바이너리 파일을 같은 방식으로 처리하면 안 됩니다.

### 알림과 오프라인 복구

온라인 클라이언트에는 long polling이나 지속 연결로 변경 사실을 알립니다. 알림에는 파일 전체를 싣지 않고 변경 버전만 알려줍니다. 클라이언트는 메타데이터를 읽고 필요한 블록을 다운로드합니다.

오프라인 클라이언트는 복귀할 때 마지막 동기화 커서 이후의 변경 목록을 가져옵니다. 알림 유실이 데이터 유실로 이어지지 않도록, 알림은 최적화이고 변경 로그가 복구의 기준이어야 합니다.

### 함정 체크

- 파일 전체를 매번 전송하면 큰 파일의 작은 수정도 큰 비용을 만듭니다.
- 객체 저장 완료 전에 메타데이터를 공개하면 다운로드할 수 없는 버전이 생깁니다.
- 마지막 쓰기 승리만 적용하면 오프라인 기기의 변경을 조용히 잃습니다.
- 알림 수신 여부를 동기화 완료로 취급하면 장기 오프라인 복구가 깨집니다.

### 오늘의 한 문장

> 파일 동기화는 파일을 복사하는 일이 아니라 블록, 버전, 충돌의 관계를 안전하게 커밋하는 일입니다.

### 30초 확인 문제

클라이언트가 모든 블록을 업로드했지만 Metadata DB 커밋 직전에 연결이 끊겼습니다. 재시도 때 블록을 다시 올려야 할까요?

### 정답과 해설

블록 해시와 업로드 세션 상태를 조회해 이미 저장된 블록은 재사용합니다. 클라이언트는 누락 블록만 올리고 메타데이터 커밋을 다시 요청합니다. 커밋 요청에는 멱등 키를 넣어 같은 버전이 두 번 생기지 않게 합니다. 커밋되지 않은 블록은 유예 기간 후 참조 여부를 확인해 정리합니다.
